# Design

The port is a **mechanical translation of the 6809 program** plus an emulation of the board around it.  No game logic was re-written.

```
 ROMs ──► reference emulator (ref/src/m6809.c + runtime/board.c, `yref`) ──► traces, dumps         (checked against MAME 0.264)
     └──► translator (translator/*.py) ──► ycode.s (native 68020 code, one block per 6809 basic block)
                                                │
 runtime/board.c (I/O, scheduler, interrupts) ◄─┤ runtime/yrt.c + ysys.s (dispatch, slow path)    ← shared with the host test harness
 runtime/render.c (tiles + sprites)             │ runtime/snsynth.c + snsynth_m68k.s (SN76489A)
 platform/ (boot, AGA display, Paula, CIA, input)  platform/gamesound.c (stream + speech glue)
```

## CPU: static translation
* `translator/model.py` discovers all code from the vectors (and the 16 computed-jump tables, analysed from the ROM), splits it into 3353 basic blocks (<= 64 cycles each) and mirrors the
  reference core's cycle counts instruction by instruction.  `emit.py` has one template per instruction form; `ytrans.py` assembles the blocks.
* Register mapping: A = d0.b, B = d1.b, X = d2.w, Y = d3.w, U = d4.w, S = a4 (a host pointer into the 64 KB image), DP-page = a2; N/Z/V/C live in the 68k CCR (same bit positions);
  E/F/H/I in a byte in memory; a3 = cycles remaining until the next scheduler event; d7 = block budget.
* Every block starts with `dbra d7` (flags untouched) and `lea -total(a3),a3`; when the budget runs out `rt_refill` computes a new one from a3.  I/O instructions call small stubs that derive
  the exact cycle stamp of the access (`now = event time - a3 - delay`).
* **Events are exact**: the scheduler (`board.c`) fires the frame IRQ and the eight NMIs at the same cycle as the reference loop.  A block is only run natively if its last instruction starts
  before the next event.  Closer to the event ("tail mode", < 128 cycles) the instructions are executed **one at a time by native single-instruction routines** (`S<addr>`, generated by the
  translator); only the interrupt entry itself goes through the C reference core (`rt_slow_c`).  The idle loop is skipped analytically when its registers are at the loop's fixed point.
* Instructions with no template (2 of 8519) and the few that change the interrupt masks (ANDCC/ORCC on I/F, PULS CC) are interpreted by the reference core (`rt_interp1`).
* Rare helpers (ROL/ROR/MUL/SEX/ABX) run the reference core on a scratch CPU, so their semantics are identical by construction.

## Video
256 x 224, 8 interleaved bitplanes, AGA **dual playfield**: playfield 1 (planes 1,3,5,7) is the tile layer, playfield 2 (planes 2,4,6,8) the sprites; pen 0 of the sprite layer is transparent, which is
exactly the arcade's priority rule, so the hardware composites.  `render.c` redraws only the tiles whose RAM changed (per-buffer shadow) and the sprites (their old rectangles are cleared first);
two buffers, flipped at vblank.  The palette is the PROM's, as 24-bit colours.

## Sound
* **SN76489A**: an *exact* model (transcribed from MAME 0.264, checked sample by sample against MAME's own audio, `sound/snref.c`), run **event-driven**: the toggle times of the three tones and the noise
  are scheduled, silent channels are advanced lazily in closed form (the noise LFSR by matrix-power jumps), and the output is integrated exactly over each Paula sample period (a box filter, no
  aliasing) with a 16-phase ordered dither to 8 bits.  `snsynth_m68k.s` is the event loop in 68020 assembly; it produces bit-identical blocks to the C loop (`sound/sntest.c`).
* One block per emulated frame, 470-472 samples (PAL; 476-478 NTSC), queued in a ring of chip-RAM blocks played by Paula channels 0 and 1 (period 124, both ears) with a pre-roll of 5 blocks
  (83 ms).  Blocks of pure silence are dropped when the stream falls behind, so the lead (and the audio latency) stays bounded without losing sound.
* **VLM5030**: the 128 phrases were captured from MAME (the chip's noise source cannot be reproduced outside MAME), stored 8-bit and LZ4-compressed (65 KB for 159 KB), decoded on demand into a
  chip-RAM buffer and played on channels 2/3 at 8135 Hz, started when the stream block of the frame in which the game started the phrase begins to play (plus the sub-frame offset as leading
  zeros), so speech and music keep the arcade's relative timing.

## Boot
A 482-byte bootblock (works with Kickstart 2/3 trackdisk, no DOS): checks the CPU, `AllocAbs`es a fixed chip-RAM region (display buffers, copper list, audio buffers), reads the payload, allocates
fast RAM (chip if there is none), **LZ4-decompresses** the image into it, applies the relocation table (the image is linked at 0x300000 and relocated), switches the OS off and jumps in.  No Kickstart file is needed or included.

## Timing
The game tick is a CIA-B timer at exactly 60.606 Hz (PAL/NTSC detected by counting beam lines).  After each emulated frame the program waits for the frame's tick; when it is behind, pictures are
skipped (at most 3 in a row) and the game catches up; it resynchronises if it falls more than 60 frames behind.
